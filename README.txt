# TinyOPDS v3.17.0 (Streenger Edition)

Лёгкий OPDS-сервер для домашних и сетевых библиотек электронных книг.

![](https://github.com/sensboston/tinyopds/blob/master/wiki/ss1.png?raw=true)

**TinyOPDS (Streenger Edition)** — расширенный и стабилизированный форк OPDS-сервера на C# / .NET Framework 4.8 (Mono для Linux и macOS). Форк рассчитан на реальные «грязные» коллекции (Либрусек, Флибуста, самиздат, выгрузки из разных редакторов): он не теряет книги из-за повреждённых или нестандартных FB2, быстро сканирует очень большие библиотеки и умеет один раз привести файлы в порядок, чтобы повторные проходы ничего не лечили заново.

Проверено на библиотеке из 498 тысяч архивов (около 486 тысяч книг в базе).

## Что нового в Streenger Edition

- **Надёжный разбор FB2.** Конец и начало блока `<description>` ищутся правильно даже у книг в формате FB3-подобных выгрузок (пространства имён вроде `xmlns:fb3d=".../FictionBook3/description"` больше не принимаются за начало описания). Санитайзер обрабатывает только начало файла, а не всю книгу целиком.
- **Исправление порчи кодировки.** Украинские буквы (`і`, `ї`, `є`, `ґ`) и русско-английские названия больше не превращаются в мусор (`Ігор` → `╡ЦНП`). Перекодировка применяется только к действительно испорченному тексту.
- **Нормализатор записывает исправления в сами книги** (один раз, а не при каждом сканировании): недостающий или пустой `document-info/id`, плохую или отсутствующую дату документа, дату книги по году издания, а также убирает HTML-мусор (`br`, `b`, `i`, `font` и др.) из описания.
- **Безопасная запись архивов.** Новый архив пишется во временный файл, сбрасывается на диск, проверяется и подменяет оригинал атомарной операцией. Сбой питания или перезагрузка в момент записи не оставят файл «нужного размера, но из одних нулей».
- **Копии оригиналов только для содержательных правок.** Если исправление касается только метаданных (id, даты, пустые `br`), копия в `libmeta/orig` не создаётся.
- **Очень быстрое повторное сканирование.** Уже известные файлы пропускаются по списку в памяти, заменённые старые версии книг не разбираются заново.
- **Ложные дубликаты.** Разные книги с одинаковым `document-info/id` получают собственные идентификаторы; шаблонные id (когда редактор копирует один `id` во все книги) не засоряют журнал.
- **Автоподстановка жанров.** Таблица соответствий нестандартных тегов (`foreign_detective`, `psy_social`, `upbringing_book`, `litrpg` и др.) справочнику жанров, расширяемая файлом `genre-aliases.txt`.
- **Буферизованный журнал.** Строки накапливаются в памяти и сбрасываются в файл раз в 30 секунд, при ошибке и при выходе.
- **Диагностика.** Строка `Scan profile` с разбивкой времени сканирования и разбивка правок санитайзера по видам в строке `auto-sanitized`.

## Быстрый старт

1. Скачайте или соберите программу (см. [Сборка](#системные-требования-и-сборка)).
2. Запустите `TinyOPDS.exe` (графическая версия) или `TinyOPDSCLI.exe` (консольная).
3. На вкладке «Сканер» укажите каталог с книгами и запустите сканирование. При первом запуске создаётся база `books.sqlite` рядом с программой.
4. Откройте `http://<адрес сервера>:<порт>/` в браузере или подключите OPDS-клиент (FBReader, AlReader, Moon+ Reader и др.) к `http://<адрес>:<порт>/opds`.

Консольная версия:

```
TinyOPDSCLI.exe -p 8080 -l "C:\Books"
```

**Совет для больших библиотек.** Перед первым запуском нормализации на настоящей библиотеке проверьте её на копии небольшой части (1–2 тысячи архивов из разных диапазонов): так вы увидите, сколько архивов будет переписано, и убедитесь в результате.

## Где что лежит

Программа работает в «портативном» режиме: данные хранятся рядом с исполняемым файлом (например, `C:\TinyOPDS`).

| Файл / каталог | Назначение |
|---|---|
| `books.sqlite` | База данных каталога (книги, авторы, серии, жанры, полнотекстовый индекс) |
| `TinyOPDS.config` | Настройки программы |
| `TinyOPDS.log` | Журнал работы |
| `normalized.index` | Индекс нормализованных архивов (см. [Нормализация](#нормализация-библиотеки)) |
| `genre-aliases.txt` | Необязательный файл с дополнительными соответствиями жанров |
| `libmeta/` | Служебный каталог рядом с корнем библиотеки: `orig` (копии оригиналов), `bad` (непрочитанные книги), `dup` (дубликаты и старые версии) |

Копирование программы на другую машину: переносите все файлы, кроме `books.sqlite*`, `TinyOPDS.config`, `*.log` и `normalized.index`, если хотите сохранить данные и настройки на месте.

## Как это работает: сканирование и разбор

### Известные файлы и список в памяти
Перед сканированием имена всех уже известных файлов загружаются в `HashSet` одним запросом. Проверка «книга уже есть?» не обращается к базе. В списке учитываются и книги, помеченные в базе как заменённые более новой версией, поэтому они не разбираются повторно.

### Чтение описания
Для каталога нужен только блок `<description>`, поэтому парсер:

1. находит открывающий тег `<description>` (с учётом префиксов вроде `ns0:`), а не просто слово «description» (оно встречается в объявлениях пространств имён FB3);
2. ищет закрывающий `</description>` по байтам (для UTF-8 и однобайтовых кодировок) и декодирует только начало файла;
3. проверяет и при необходимости исправляет только этот фрагмент (`Fb2Sanitizer`), а не всю книгу в несколько мегабайт;
4. разбирает XML описания, автор, жанры, серию, дату и т. д.

Если описание после этого всё же не читается, включается запасной путь: санитайзер по всему файлу. Раньше санитайзер прогонялся по всему файлу для каждой книги, и именно это занимало почти всё время разбора (около 98 %).

### Санитайзер (`Fb2Sanitizer`)
Шаги по порядку: пространства имён и префиксы, объявление `xmlns:xlink` / `xmlns:l`, перекодировка испорченной кириллицы, запрещённые управляющие символы, амперсанды, HTML-мусор, одиночные `<`, выравнивание вложенности тегов. Правки в журнале описываются по видам:

| Вид | Значение |
|---|---|
| `ns`, `ns0close`, `xlink` | пространства имён и префиксы |
| `cyr` | исправление испорченной кодировки кириллицы |
| `ctrl` | запрещённые управляющие символы |
| `amp` | неэкранированные `&` и неизвестные сущности |
| `junk` | HTML-мусор (`br`, `b`, `i`, `font`, `div`, …) |
| `lt` | одиночные `<` в тексте |
| `lhref` | не объявлен префикс `l:` |
| `nest` | выравнивание вложенности тегов |

Важные свойства:
- Корректный XML не «исправляется» шагом экранирования `<`: неизвестный, но правильный тег (например, `<book-author>` в `publish-info`) остаётся тегом.
- Перекодировка кириллицы выполняется, только если после неё кириллицы заметно больше (минимум на 20 % и на 8 букв), она преобладает среди букв и в тексте нет символов псевдографики. Так украинские и билингвальные тексты не портятся, а настоящий случай «CP866, прочитанная как 1251» по-прежнему чинится.

### Книги без автора
Если в `title-info` нет `<author>`, автор выбирается по цепочке: составитель из названия издания → автор из заголовка тела книги → `Неизвестный автор`. Автор из `document-info` не используется (это создатель файла, а не книги).

### Идентификаторы и коллизии
Если у двух книг совпадает `document-info/id`, но различаются название, серия и номер, а размер отличается более чем на 25 %, второй книге присваивается собственный идентификатор. Для каждого такого id в журнал пишутся первые три предупреждения, затем одна информационная строка и тишина.

### Замена версий и дубликаты
Если новая версия книги встречается вместе со старой (в базе или в одной пачке при сканировании), старая версия заменяется. С включённой нормализацией старые версии и дубликаты переносятся в `libmeta/dup`, поэтому повторные сканирования не возвращаются к ним.

## Нормализация библиотеки

Нормализатор запускается перед сканированием (настройка `NormalizeLibrary`). Он проходит по архивам библиотеки, чинит поврежденные FB2 и записывает недостающие метаданные прямо в файлы, чтобы это не приходилось делать при каждом сканировании.

> **Внимание: первый прогон занимает много времени.** При первом запуске индекс `normalized.index` пуст, поэтому программа проверяет каждый архив. На больших библиотеках (сотни тысяч архивов) это может занять несколько часов. Следите за ходом по журналу: строки `LibraryNormalizer: …`, итог `LibraryNormalizer: done. …`. Последующие запуски пропускают уже обработанные архивы и проходят за секунды (поле `skipped(indexed)`).

### Что исправляется

**Содержательные правки (с копией оригинала в `libmeta/orig`):**
- повреждённая разметка FB2: незакрытые теги, закрывающие теги без пары, регистр, одиночные `<`, запрещённые символы;
- нестандартные жанры, авторы, идентификаторы картинок, перенос блоков из абзацев, очистка тела книги.

**Лёгкие правки (без копии оригинала):**
- `document-info/id`: пустой или отсутствующий идентификатор заменяется на детерминированный UUID (строится от пути `архив@запись`);
- `document-info/date`: нет или не читается, подставляется дата записи в архиве;
- `title-info/date` (дата книги): нет читаемой даты, берётся год из `publish-info/year`; если и его нет, подставляется текущая дата. Если в дате есть свободный текст («конец XVI века»), текст сохраняется, добавляется только атрибут `value`;
- недостающий `document-info` создаётся целиком (`author`, `date`, `id`, `version`);
- HTML-элементы в описании (`br`, `b`, `i`, `u`, `em`, `font`, `span`, `div`, `li`, …): пустые удаляются, остальные заменяются своим содержимым;
- порядок элементов описания приводится к порядку схемы FB2.

### Версии индекса
Файл `normalized.index` хранит для каждого архива состояние, размер, время изменения и версию логики:

| Версия | Что добавлено |
|---|---|
| 1 | починка повреждённой разметки |
| 2 | запись id и дат в книги |
| 3 | удаление HTML-мусора из описания |

Записи с версией ниже текущей перепроверяются: после обновления программы первый прогон проходит по всем архивам заново (в основном это чтение), но переписываются только те, которым действительно что-то нужно. Чтобы перепроверить всё принудительно, удалите `normalized.index`. Индекс привязан к одной библиотеке.

### Безопасная запись
Переписанный архив создаётся во временном файле, данные сбрасываются на диск (`Flush(true)`), архив проверяется (читается, число записей совпадает), после чего подменяет оригинал операцией `File.Replace`. Оригинал не пропадает до тех пор, пока новый файл не встал на его место.

### Пример прогона на большой библиотеке
- Библиотека из 498 331 архива: починено 3 303 архива, ошибок нет (первый вариант нормализации).
- Тестовая выборка из 19 219 архивов (HDD, 36-поточная машина): проход версии 2 занял около 16 минут, переписано 15 328 архивов.
- Тестовый набор из 3 363 проблемных архивов: проход версии 3 переписал 2 595 архивов (8 437 исправлений), ошибок 0; после этого сканирование дало 0 строк `auto-sanitized`.

## Служебный каталог libmeta

Каталог создаётся рядом с корнем библиотеки (например, для `F:\Libruks` это `F:\libmeta`).

| Подкаталог | Содержимое |
|---|---|
| `orig` | Копии архивов до содержательных правок (настройка `KeepOriginals`) |
| `bad` | Книги, которые не удалось прочитать (нет названия, автора и жанров) |
| `dup` | Дубликаты и старые версии книг, заменённые более новыми |

Файлы переносятся после завершения сканирования, если включена нормализация. Всё можно вернуть обратно в библиотеку вручную: программа подхватит их при следующем сканировании.

## Жанры и файл genre-aliases.txt

Тег жанра книги проверяется по справочнику (`Resources/genres.xml`) последовательно:

1. как есть (регистр не важен; в базу пишется написание из справочника, например `AU`, а не `au`);
2. после очистки: убираются невидимые символы, достаётся тег из скобок (`Детективная фантастика(sf_detective` → `sf_detective`), кириллические «двойники» латинских букв заменяются латиницей;
3. замена `-` ↔ `_`;
4. таблица подстановок.

Таблица подстановок встроена в программу (около 70 соответствий: `foreign_detective` → `detective`, `psy_social` → `sci_psychology`, `upbringing_book` → `family_parenting`, `litrpg` → `sf_litrpg`, `comp_all` → `computers`, `thriller_mystery` → `thriller`, `unrecognised` → `other`, теги вида `prose_all` / `nonf_all` / `humor_all` → корневой жанр раздела и другие).

Её можно расширять и переопределять без перекомпиляции файлом `genre-aliases.txt` в папке данных программы:

```
# старый_тег=новый_тег
foreign_desc=foreign_prose
st=other
```

Правила: одна пара на строку, строки с `#` — комментарии, регистр не важен, целевой тег должен существовать в справочнике. Теги, которые не удалось сопоставить, перечисляются в журнале строкой `Batch insert: N invalid genre tags skipped. Tags: …`: именно по ним удобно дополнять файл.

Подстановка действует при добавлении книг в базу. Чтобы применить её к уже загруженным книгам, нужен повторный разбор (пустая база).

## Журнал и диагностика

Журнал `TinyOPDS.log` буферизуется: строки накапливаются в памяти и записываются в файл раз в 30 секунд, при накоплении 5 000 строк, при ошибке (уровень `E`) и при выходе из программы. Кнопка «Посмотреть лог» сбрасывает очередь перед открытием. Интервал задаётся `Log.FlushIntervalSeconds` (0 — писать каждую строку сразу).

### Основные сообщения

| Сообщение | Что означает |
|---|---|
| `LibraryNormalizer: done. scanned=…, repaired=…, fixes=…, skipped(indexed)=…, errors=…` | Итог нормализации. `skipped(indexed)` — пропущенные по индексу архивы |
| `fb2 repaired (N fixes, metadata only, no backup)` | Архив переписан, правки только метаданных, копия не создавалась |
| `fb2 sanitized (N syntax fixes)` | Исправлена разметка, оригинал скопирован в `libmeta/orig` |
| `FB2Parser: auto-sanitized stream for … (N fixes: amp=2,junk=1)` | Описание понадобилось исправлять при разборе (после нормализации такие строки должны исчезнуть) |
| `Scan profile: …` | Разбивка времени сканирования (открытие архивов, проверка известных файлов, чтение и разбор, обновление интерфейса) |
| `Scan profile (read/parse of N books): …` | Разбивка внутри разбора: распаковка записи, копирование в буфер, чтение описания, разбор описания |
| `Document ID collision … are different books, assigning a new ID` | Разные книги с одинаковым `document-id`; новая книга получила собственный id |
| `In-batch replacement: Название vX replaces vY` | Новая версия заменила старую в пачке; старая уйдёт в `libmeta/dup` |
| `Book.IsValid=false: title=…, utf=…, authors=…, genres=…` | Книга не прошла проверку; поле показывает причину |
| `Failed to read description block …` | Не удалось прочитать описание |
| `Batch insert: N invalid genre tags skipped. Tags: …` | Нераспознанные жанры (дополните `genre-aliases.txt`) |

## Производительность

Измерения на тестовых наборах (отладочная машина: 18 ядер / 36 потоков, жёсткие диски; боевой сервер: SSD).

| Показатель | До | После |
|---|---|---|
| Чтение описания одной книги | около 436 мс (проблемные файлы), 75 мс (обычные) | около 1 мс |
| Сканирование 3 363 проблемных книг | 106,7 с | 72–76 с (остальное — чтение с HDD) |
| Повторное сканирование библиотеки 498 тысяч архивов с новыми книгами | 1 ч 02 мин → 24 мин 42 с | около 3,5 минут (6 047 новых книг, остальные пропущены по списку) |
| Полный ребилд базы с нуля (~495 тысяч книг) | более часа | порядка 20–25 минут (оценка по темпу пачек) |

Основное ускорение даёт то, что санитайзер больше не проходит по всей книге, а ограничивается началом файла. Остаток времени — чтение и распаковка записей с диска.

## Обновление, ребилд базы, восстановление

### Обновление программы на сервере
1. Остановите TinyOPDS на сервере.
2. Сделайте резервные копии `books.sqlite`, `TinyOPDS.config` и `normalized.index`.
3. Скопируйте новую сборку, не затрагивая данные: из `Release\TinyOpds3.15.5` в папку программы, исключая `books.sqlite*`, `TinyOPDS.config`, `*.log`, `*.pdb`, `normalized.index`:

```powershell
robocopy "<папка сборки>\TinyOpds3.15.5" "C:\TinyOPDS" /E /XF books.sqlite* TinyOPDS.config *.log *.pdb normalized.index
```

4. Запустите программу и проверьте начало журнала (строка `TinyOPDS version … started`, итог нормализатора).

### Когда нужен ребилд базы
После обновления разбора (жанры, исправление искажённых названий) уже загруженные книги остаются как были. Чтобы применить улучшения ко всей библиотеке, остановите программу, сохраните `books.sqlite` и запустите сканирование с пустой базой (удалите `books.sqlite`). Индекс `normalized.index` можно оставить.

### Проверка библиотеки на «нулевые» архивы
Если сервер перезагружался во время записи файлов, файл может остаться нужного размера, но заполненным нулями. Такие архивы выглядят как `не zip по началу` или «Не удается найти конец записи главного каталога». Быстрая проверка (читает только первые байты каждого файла):

```powershell
Get-ChildItem 'F:\Libruks' -Recurse -Filter *.zip -File | ForEach-Object {
  $fs = [IO.File]::OpenRead($_.FullName); $b = New-Object byte[] 4; [void]$fs.Read($b, 0, 4); $fs.Close()
  if (-not ($b[0] -eq 0x50 -and $b[1] -eq 0x4B)) { $_.FullName }
}
```

Восстанавливайте такие файлы из резервной копии или исходной раздачи. Начиная с текущей версии нормализатор пишет архивы безопасно (см. выше), но старые версии программы могли оставить такие файлы при аварийной остановке.

## Интеграция upstream 3.16–3.17

- **Любые алгоритмы сжатия ZIP**: PPMd, LZMA, BZip2, Deflate64 через `SharpCompress` и `ZipEntryReader`.
- **Полнотекстовый поиск FTS5**: корректная обработка запросов с кавычками, пунктуацией и спецсимволами.
- **Однократная миграция индекса `BooksFTS`**: очистка сиротских записей и дубликатов с фиксацией версии через `PRAGMA user_version`.
- **Производительность**: кэширование статистики жанров и серий, быстрый переход по авторам, постраничная догрузка связей книг.
- **Безопасность и совместимость**: HTTP Basic Auth по RFC 7617 (двоеточия в паролях), защита веб-читалки от XSS, ASCII-имена файлов в `Content-Disposition`, MIME-тип `application/fb2+zip`.
- **Кодировки имён в ZIP**: Latin1, CP866, CP1251 без кракозябр при сканировании, чтении и отдаче обложек.

### Исправления интерфейса
- Метки на вкладке «Сканер» подбирают размер автоматически (`AutoSize`).
- Статус «Нормализация архивов» на время нормализации.
- Обновлён обработчик настройки «Отслеживать изменения».
- На вкладке «О программе»: обозначение Streenger Edition, ссылка на репозиторий форка, кнопка Readme (открывает локальный `README.txt`, при его отсутствии предлагает страницу на GitHub).

## Системные требования и сборка

- **ОС**: Windows 10/11, Windows Server (или Linux / macOS под Mono 6.0+).
- **Среда выполнения**: .NET Framework 4.8 (Windows) или Mono.
- **Память**: от 150–200 МБ для больших коллекций (100 000+ книг).
- **Диск**: для нормализации желательно свободное место под `libmeta/orig`, если включено сохранение оригиналов.

Сборка через Visual Studio или MSBuild:

```powershell
MSBuild.exe TinyOPDS.sln /p:Configuration=Release /t:Rebuild
```

Запуск:
- GUI: `TinyOPDS\bin\Release\TinyOpds3.15.5\TinyOPDS.exe`
- CLI: `TinyOPDSCLI\bin\Release\TinyOPDSCLI.exe -p 8080 -l "C:\Books"`

## Известные ограничения

- Нормализатор работает в один поток: на HDD параллельная работа не ускорила бы запись, а на SSD это ещё предстоит оценить.
- Правила подстановки жанров применяются при добавлении книг; для уже загруженных нужен повторный разбор.
- Даты в нестандартной записи (например, `2001г` без пробела) могут не распознаваться и заменяться запасной датой.
- Отображение интерфейса при разных масштабах Windows требует отдельной проверки.

## English summary

TinyOPDS (Streenger Edition) is a hardened fork of the lightweight OPDS server for home and network libraries, tuned for large, messy FB2 collections.

- **Robust FB2 parsing**: the real `<description>` start is found even for FB3-style namespaces; the end of the description is located by bytes; the sanitizer works only on the head of the file. Reading a description went from about 436 ms (problem files) / 75 ms (typical) to about 1 ms per book.
- **No more mangled text**: Ukrainian letters and bilingual titles are no longer recoded into garbage; recoding is applied only when it clearly helps.
- **Fixes persisted in the books**: the normalizer writes missing document ids and dates, derives book dates from the publication year, and removes HTML junk from the description, once, so later scans have nothing to repair.
- **Crash-safe rewrite**: temporary file, flush to disk, verification, atomic `File.Replace`.
- **Backups only for content fixes**: metadata-only changes do not copy the original to `libmeta/orig`.
- **Fast rescans**: known files are skipped via an in-memory set; replaced older versions go to `libmeta/dup`. Example: a 498k-archive library rescan with 6,047 new books took about 3.5 minutes; a full database rebuild takes about 20–25 minutes.
- **Genre aliasing**: a built-in table plus an optional `genre-aliases.txt` (`old_tag=new_tag`) map non-standard tags to the genre dictionary.
- **Buffered log** (30 s flush, immediate on errors and exit) and a detailed `Scan profile` line.

See [`RELEASE_NOTES_3.17.md`](RELEASE_NOTES_3.17.md) for the change list.
