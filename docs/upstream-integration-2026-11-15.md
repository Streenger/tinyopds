# TinyOPDS: выборочное обновление и список конфликтов

Подготовлен перенос независимых исправлений upstream в Streenger Edition. Полное слияние намеренно не выполнено: спорные изменения выделены для последующего обсуждения, исходная ветка `master` не менялась.

## Границы сравнения

- **Форк:** `Streenger/tinyopds`, исходный коммит `5e6225f2f53bcc5639149388badd0606ad938f8a`.
- **Upstream:** `sensboston/tinyopds`, зафиксирован на `1b92e26a1fc11364c2d09536f9f41ee0edc2dd23`.
- **Общая база графа:** `82fea19a2a424d09fddd380750effbceba10bc3f`; после неё upstream содержит 70 коммитов, но это не 70 отсутствующих исправлений: изменения 3.16–3.17 уже переносились в форк вне прямой merge-истории ([сравнение upstream](https://api.github.com/repos/sensboston/tinyopds/compare/82fea19a2a424d09fddd380750effbceba10bc3f...1b92e26a1fc11364c2d09536f9f41ee0edc2dd23)).
- **Рабочая ветка:** `chore/upstream-safe-2026-11-15`, отдельный обычный Git-клон; локальный каталог Windows пользователя этой операцией не изменён.
- **Стратегия:** анализ исходников и зависимостей, пробное полное слияние через `git merge-tree`, затем точечный перенос проверенных патчей; не `merge -X theirs` и не замена каталога upstream.

Названия релизов upstream не присваивались форку: выборочный набор исправлений не равнозначен полной версии 3.21. Теги и GitHub releases не создавались.

## Сохранённые доработки Streenger Edition

Исходники нормализатора, FB2-парсера, санитайзера, сканеров, детектора дублей, менеджера БД и основного класса библиотеки не изменены относительно исходного коммита форка. В `MainForm.cs` затронуты только инициализация и обработчики окна/трея, а не запуск нормализации или обновление статуса сканера.

- **Нормализация:** сохранены индекс и его версионирование, атомарная подмена архивов, проверка записи и правила хранения оригиналов.
- **FB2:** сохранены защита украинского и смешанного текста, исправление некорректного XML и отказ от некорректных исправлений.
- **Сканирование:** сохранены предзагрузка имён, пропуск известных файлов, профилирование, собственная обработка совпадающих ID и сопоставление жанров.
- **Интерфейс форка:** About, Readme, чекбокс слежения, подписи и счётчики сканера не заменены upstream-версиями.
- **Данные:** миграции не добавлены, библиотека пользователя не открывалась и не переписывалась.

## Конфликты для решения

«Чисто применяется» не означает «безопасно переносится». Ниже вместе перечислены текстовые конфликты и изменения, которые формально применяются, но меняют правила обработки данных либо зависят от отложенной архитектуры.

| Блок | Почему отложен | Что решить |
|---|---|---|
| **Счётчики и пакетная запись 3.18** | Перестройка прохода сканирования, ожидание сохранения последних пакетов и общий `BookBatchWriter` затрагивают собственные статусы, нормализацию и оптимизации форка ([c10df91](https://github.com/sensboston/tinyopds/commit/c10df9112e0807b36036df8a340647b8bff1d498), [9b9c0b7](https://github.com/sensboston/tinyopds/commit/9b9c0b774d2414b61ae0eb17d6dadf9f4030db37)). | Переносить отдельной задачей с проверкой повторных проходов, остановки и последнего неполного пакета; не заменять сканер целиком. |
| **Новый алгоритм дублей** | Меняется ключ сравнения: серии и отчества игнорируются, нормализуются переводчики и номера томов; это может иначе объединить записи, чем нынешняя логика форка ([937acbf](https://github.com/sensboston/tinyopds/commit/937acbf5242e37c7a91aa3cc13865284e82eec32)). | Сначала сравнить решения старого и нового алгоритмов на контрольной коллекции; отдельно решить, какие различия допустимо считать одной книгой. |
| **Watcher** | Ожидание окончания копирования, переименования, очереди и пауза полезны, но патч зависит от пакетной записи и согласования со сканером; текстовая применимость обманчива ([587f897](https://github.com/sensboston/tinyopds/commit/587f897a2d069768106667c2e7c8ea9140664b7a)). | Переносить после решения по writer/сканеру; проверить большие ZIP, временные имена, перемещение папок и нормализацию при включённом слежении. |
| **Веб-загрузка и удаление книг 3.19** | Новый сценарий записи/удаления файлов связан с HTTP, БД, слежением и восстановлением заменённых копий ([e36a2c9](https://github.com/sensboston/tinyopds/commit/e36a2c9d2d32e381787104224626b2227a5a7868)); исправление устаревшей обложки зависит от него ([60de25e](https://github.com/sensboston/tinyopds/commit/60de25e2044ee91e91258edcb07b66427ca31489)). | Нужна ли вообще загрузка из браузера; если да, определить права, лимиты, каталог и связь с нормализатором до переноса. |
| **Все серии и их нормализация 3.20** | Требуются изменения модели книги, таблиц, чтения FB2/EPUB, интерфейса и одноразовая миграция названий; отдельно взятую нормализацию серии из EPUB-парсера переносить нельзя ([31fe50c](https://github.com/sensboston/tinyopds/commit/31fe50c7d01f2a26ad9ce7b660cdc701e6b8e80e)). | Нужны ли несколько серий для одной книги и как сохранять исходные названия; сначала резервная копия и пробная миграция. |
| **Автоматическая установка обновления** | Новый установщик заменяет работающий EXE, а источник релизов в upstream `UpdateChecker` указывает на `sensboston/tinyopds`; простой перенос создаёт риск заменить Streenger Edition оригинальной программой ([31fe50c](https://github.com/sensboston/tinyopds/commit/31fe50c7d01f2a26ad9ce7b660cdc701e6b8e80e)). | Если нужен автоустановщик, адаптировать источник, имена артефактов, версии и откат именно для форка; до этого не включать. |
| **Поиск ё/е и быстрый список авторов 3.21** | Затронуты FTS, миграции/переиндексация, библиотека и кеш авторов; на большой библиотеке нужен отдельный замер и проверка восстановления ([b422cff](https://github.com/sensboston/tinyopds/commit/b422cffcc6d7292435965033d728937b4c2ff247)). | Выделить в следующий полезный перенос после сохранения базы; согласовать допустимое время первого запуска и необходимость полного перестроения. |
| **Авторизация, баны, IPv6 и журнал** | Новая архитектура затрагивает HTTP, настройки, сохранение банов и ротацию логов, пересекающуюся с буферизованным журналом форка ([b422cff](https://github.com/sensboston/tinyopds/commit/b422cffcc6d7292435965033d728937b4c2ff247)); исправление пустого Authorization рассчитано уже на неё ([1b92e26](https://github.com/sensboston/tinyopds/commit/1b92e26a1fc11364c2d09536f9f41ee0edc2dd23)). | Решить отдельно для вашей схемы публикации сервера; не переносить последний маленький фикс без его контекста. |
| **Обложки после входа с того же IP** | Даже чистый патч меняет правило доступа: другой запрос с уже авторизованного IP сможет получить изображение ([05533a6](https://github.com/sensboston/tinyopds/commit/05533a6038491a08a3445509cf5f2a922f19770c)). | Допустимо ли это за NAT и обратным прокси; если нет, сохранять проверку учётных данных на каждом запросе. |
| **Год публикации** | Неперенесённая часть патча определяет отсутствие собственной даты по косвенным признакам; в форке даты уже восстанавливаются нормализатором ([8f246b7](https://github.com/sensboston/tinyopds/commit/8f246b7cb2b7ede7a6df0234feac8107f6db512d)). | Различать дату публикации, документа и файла явно; не менять отображение эвристикой до проверки нормализованных книг. |
| **Docker и публикация сборок** | Контейнерные изменения рассчитаны на новые режимы CLI/watch/scan, а прямой перенос release workflows затрагивает публикацию оригинальной программы. | Нужен ли контейнер именно Streenger Edition; собирать из форка, а не подменять его upstream-образом. |

Рекомендуемый порядок дальнейшего обсуждения: поиск ё/е; затем пакетная запись и Watcher; затем серии. Правила дублей и автоустановщик требуют отдельного явного решения, а веб-загрузку и Docker стоит брать только при реальной необходимости.

## Проверка

- **Сборки в sandbox:** GUI и CLI собраны в Release через Mono/xbuild с Roslyn 4.8; исходная версия форка также собиралась в той же среде.
- **C# проверки:** по 25 успешных проверок для GUI и CLI; пять вариантов EPUB-пути, ресурсы склонений, состояния кеша, порядок SQL-связей, встроенный XSL и языковые атрибуты.
- **SQL:** три успешных теста настоящих SQL-запросов на временной SQLite; до переноса соответствующих исправлений эти сценарии воспроизводили ошибки.
- **Читалка:** успешный JS-тест четырёх состояний языка; отсутствие метода до переноса также воспроизведено.
- **Браузер:** синтетический каталог отрендерен настоящим XSL из сборки; на ширине 390 px описание свёрнуто до 273 px, кнопки раскрытия/сворачивания меняют `aria-expanded`; ресурсы каталога получены с HTTP 200.
- **Windows CI:** код на коммите `29f8027b9d77df238e8f32b55d771ed1570d034e` прошёл сборку GUI/CLI с 0 ошибками и 0 предупреждениями компилятора, по 25 C# проверок, три SQL-теста и JS-тест; сборки приложены как `tinyopds-upstream-safe-1`, release не создавался ([успешный запуск GitHub Actions](https://github.com/Streenger/tinyopds/actions/runs/43761019233)).
- **Статическая проверка:** `git diff --check`, анализ областей изменения и сравнение защищённых исходников с исходной версией форка.

Предупреждения Mono о старом toolset и неизвестных секциях `.sln` относятся к среде проверки. Чтобы собрать на регистрозависимой ФС, временно создавалась ссылка `FB2Parser.cs` на имеющийся `fb2Parser.cs`; Windows-postbuild отключался только параметром команды, не изменением проекта.

Живую библиотеку пользователя, нормализацию сотен тысяч архивов, реальный Google Translate и поведение Windows при отключении монитора здесь не проверяли. Не следует считать успешную компиляцию или наличие типов доказательством этих сценариев; контрольный план находится в `tests/README.md`.

## Получение и откат

После сохранения собственной незакоммиченной работы получить ветку можно так:

```powershell
git fetch origin
git switch --track origin/chore/upstream-safe-2026-11-15
```

Если локальная ветка уже существует, достаточно `git switch chore/upstream-safe-2026-11-15`, а не повторного `--track`. Сначала собрать и проверить копию небольшой библиотеки; рабочую установку обновлять только после резервной копии.

Возврат к прежнему исходному коду: `git switch master`, поскольку эта интеграция `master` не меняет. Это не откатывает данные приложения автоматически: для рабочей установки нужно восстановить сохранённые EXE/конфигурацию/базу при закрытом сервере.

Pull request намеренно не создавался: существующий PR-workflow репозитория публикует prerelease и рассчитан на другие выходные пути. Новый проверочный workflow не использует release-права и не заменяет этот старый процесс.
