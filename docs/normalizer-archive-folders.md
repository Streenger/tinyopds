# Нормализация: отдельная папка для каждого многокнижного архива

Многокнижный ZIP теперь раскладывается в одноимённую подпапку рядом с исходным архивом. Это не позволяет книгам из всех сборников накапливаться в одном корневом каталоге; правило «один ZIP = одна книга» сохраняется.

## Структура результата

Для `L:\FLIBUSTA\lib.rus.ec\fb2-000024-030559.zip`:

```text
L:\FLIBUSTA\lib.rus.ec\
  fb2-000024-030559\
    000024.zip
      000024.fb2
    000025.zip
      000025.fb2
```

Имена книг в примере условные. Для `fb2-000007-788888_lost.zip` создаётся папка `fb2-000007-788888_lost`; имя папки берётся из имени исходного ZIP без последнего расширения, включая суффикс `_lost`.

## Что остаётся прежним

- **Одиночные ZIP:** архивы с одной книгой не перемещаются и не получают дополнительную папку. Уже разложенные в корень одиночные ZIP автоматически не перегруппировываются.
- **Книги без архива:** отдельные FB2/EPUB упаковываются рядом с собой, как прежде.
- **Существующая папка:** используется повторно; совпадающие имена ZIP получают суффиксы ` (2)`, ` (3)` и далее, без перезаписи существующих файлов.
- **Оригинал сборника:** при `KeepOriginals=true` перемещается в настроенный `libmeta/orig`; при `false` после завершения разделения удаляется. Перед первым запуском новой сборки рекомендуется резервная копия и проверка на копии одного сборника.
- **Ошибка создания папки:** регистрируется как ошибка нормализации; исходный архив остаётся на месте.
- **Починка и каталог:** алгоритмы восстановления FB2, версия `normalized.index` и сканер не изменены. Штатный `FileScanner` по умолчанию рекурсивно обходит подпапки.

Изменение находится в общем `LibraryNormalizer.cs`, который используется GUI и CLI. Оно не импортирует ни один из отложенных блоков upstream.

## Автоматическая проверка

`tests/NormalizerLayoutChecks.cs` вызывает настоящий `LibraryNormalizer.Normalize` из выбранного EXE через reflection, не запускает приложение или сервер и работает только с новым синтетическим каталогом. Настройка `MetaPath` меняется только в памяти процесса теста; пользовательские настройки не сохраняются.

В этих проверках `repairFb2=false`: проверяется раскладка, чтение всех созданных ZIP и сохранность исходных байтов, а не синтаксис FB2 или алгоритм его восстановления. Полноразмерный прогон реальной библиотеки и визуальная проверка GUI этим не заменяются.

Проверяются 11 сценариев: многокнижный сборник, вложенный каталог и `_lost`, одинаковые имена книг в разных сборниках, существующая папка с конфликтом имени файла, совпадающие базовые имена записей, повторный запуск, одиночный ZIP и отдельная книга, сохранение оригинала, блокирующий файл вместо папки, пустой ZIP и сборник из 1024 книг с чтением каждого результата.

Запуск в Windows PowerShell из корня репозитория после сборки:

```powershell
$checkDir = Join-Path $env:TEMP ("tinyopds-layout-" + [guid]::NewGuid().ToString("N"))
New-Item -ItemType Directory -Path $checkDir | Out-Null
$compiler = Join-Path $env:WINDIR 'Microsoft.NET\Framework64\v4.0.30319\csc.exe'
$checks = Join-Path $checkDir 'NormalizerLayoutChecks.exe'
& $compiler /nologo "/out:$checks" /r:System.IO.Compression.dll /r:System.IO.Compression.FileSystem.dll tests\NormalizerLayoutChecks.cs
if ($LASTEXITCODE -ne 0) { throw 'Test compilation failed' }
$build = 'dist\normalizer-archive-folders-2026-11-18'
& $checks "$build\GUI\TinyOPDS.exe" (Join-Path $checkDir 'gui')
if ($LASTEXITCODE -ne 0) { throw 'GUI layout checks failed' }
& $checks "$build\CLI\TinyOPDSCLI.exe" (Join-Path $checkDir 'cli')
if ($LASTEXITCODE -ne 0) { throw 'CLI layout checks failed' }
```

Тест отказывается использовать уже существующий каталог для своих данных. Созданные искусственные архивы остаются в указанном временном каталоге для проверки.
