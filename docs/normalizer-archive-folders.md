# Нормализация: отдельная папка для каждого многокнижного архива

Многокнижный ZIP теперь раскладывается в одноимённую подпапку рядом с исходным архивом. Это не позволяет книгам из всех сборников накапливаться в одном корневом каталоге; правило «один ZIP = одна книга» сохраняется.

## Структура результата

Для `L:\FLIBUSTA\lib.rus.ec\fb2-000024-030559.zip`:

```text
L:\FLIBUSTA\lib.rus.ec\
  fb2-000024-030559\
    000024.zip
      000024.fb2
    000025.zip
      000025.fb2
```

Имена книг в примере условные. Для `fb2-000007-788888_lost.zip` создаётся папка `fb2-000007-788888_lost`; имя папки берётся из имени исходного ZIP без последнего расширения, включая суффикс `_lost`.

## Что остаётся прежним

- **Одиночные ZIP:** архивы с одной книгой не перемещаются и не получают дополнительную папку. Уже разложенные в корень одиночные ZIP автоматически не перегруппировываются.
- **Книги без архива:** отдельные FB2/EPUB упаковываются рядом с собой, как прежде.
- **Существующая папка:** используется повторно; совпадающие имена ZIP получают суффиксы ` (2)`, ` (3)` и далее, без перезаписи существующих файлов.
- **Оригинал сборника:** удаляется сразу после успешной записи всех книг в отдельные ZIP, до перехода к следующему сборнику, независимо от `KeepOriginals`. Переноса в `libmeta/orig` для разделённых сборников больше нет. Перед первым запуском новой сборки рекомендуется резервная копия и проверка на копии одного сборника.
- **Поархивное завершение:** все выходные ZIP записываются и закрываются без сброса после каждой книги; затем закрывается исходный ZIP и проверяется число книг. После этого одним проходом каждый ZIP сборника (записанный сейчас или пропущенный как уже существующий) открывается и сбрасывается на диск через `Flush(true)` (FlushFileBuffers). Если хотя бы один файл сбросить не удалось, обработка завершается ошибкой и исходник остаётся. Только после этого исходник удаляется внутри обработчика этого архива. Общей отложенной очистки в конце прохода нет. При исключении во время записи исходный архив не удаляется.
- **Лог перед следующим архивом:** после успешного удаления записывается событие `LibraryNormalizer: source archive deleted` с полями пути исходника, `output` и `books`; сразу вызывается `Log.Flush()`, без ожидания таймера. Используются существующие настройки логирования: для сохранения сообщения должны быть включены файловый лог и уровень Info. При ошибке удаления пишется `delete original failed`, без ложного сообщения об успехе.
- **Резервные копии починки:** `KeepOriginals` продолжает действовать для содержательных исправлений FB2 в проходе починки; этот механизм не изменён.
- **Ошибка создания папки:** регистрируется как ошибка нормализации; исходный архив остаётся на месте.
- **Починка и каталог:** алгоритмы восстановления FB2, версия `normalized.index` и сканер не изменены. Штатный `FileScanner` по умолчанию рекурсивно обходит подпапки.

Изменение находится в общем `LibraryNormalizer.cs`, который используется GUI и CLI. Оно не импортирует ни один из отложенных блоков upstream.

## Повторный запуск после прерывания

Если обработка сборника прервалась, часть книг уже лежит в его папке, а исходник не удалён. При повторном запуске для каждой книги перебираются имена `name.zip`, `name (2).zip`, …:

- ZIP с ровно одной записью того же имени, того же размера и того же CRC32 — книга уже записана: она пропускается, копия не создаётся. CRC32 и размер берутся из центрального каталога обоих ZIP, содержимое не распаковывается.
- ZIP не читается (обрыв записи: центральный каталог пишется последним) — файл перезаписывается на том же месте, в лог пишется `replacing unreadable partial ZIP`.
- Другой корректный ZIP с тем же именем — пробуется следующее имя, как и раньше.

Пропущенные книги засчитываются в общую сверку, поэтому исходник удаляется после того, как все книги либо записаны, либо уже были на месте. Строка лога о завершении содержит `skippedExisting=K`; в результате счётчик `BooksSkippedExisting`. Копии « (2)», созданные прежними версиями до этого исправления, автоматически не удаляются.

## Автоматическая проверка

`tests/NormalizerLayoutChecks.cs` вызывает настоящий `LibraryNormalizer.Normalize` и его поархивный обработчик из выбранного EXE через reflection, не запускает приложение или сервер и работает только с новым синтетическим каталогом. `MetaPath` и путь лога задаются только в памяти процесса теста; лог направляется в каталог соответствующего искусственного сценария, пользовательские настройки не сохраняются.

В этих проверках `repairFb2=false`: проверяется раскладка, чтение всех созданных ZIP и сохранность исходных байтов, а не синтаксис FB2 или алгоритм его восстановления. Полноразмерный прогон реальной библиотеки и визуальная проверка GUI этим не заменяются.

Проверяются 20 сценариев: многокнижный сборник, вложенный каталог и `_lost`, одинаковые имена книг в разных сборниках, существующая папка с конфликтом имени файла, совпадающие базовые имена записей, повторный запуск, одиночный ZIP и отдельная книга, удаление сборника даже при включённом `KeepOriginals`, блокирующий файл вместо папки, ошибка после записи первой книги с сохранением полного исходника, удаление и запись в лог внутри поархивного обработчика до обработки следующего сборника, немедленное наличие сообщения в файле при таймере логирования на час, ошибка удаления заблокированного исходника без ложного сообщения об успехе, пустой ZIP, сборник из 1024 книг с чтением каждого результата, а также повторный запуск после прерывания: пропуск уже записанной книги без « (2)», другая книга того же имени и размера с иным CRC32, перезапись недописанного ZIP и повтор с совпадающими базовыми именами без « (3)», сохранение исходника, если выходной ZIP нельзя сбросить на диск. Проверка блокировки удаления рассчитана на файловую семантику Windows.

Запуск в Windows PowerShell из корня репозитория после сборки:

```powershell
$checkDir = Join-Path $env:TEMP ("tinyopds-layout-" + [guid]::NewGuid().ToString("N"))
New-Item -ItemType Directory -Path $checkDir | Out-Null
$compiler = Join-Path $env:WINDIR 'Microsoft.NET\Framework64\v4.0.30319\csc.exe'
$checks = Join-Path $checkDir 'NormalizerLayoutChecks.exe'
& $compiler /nologo "/out:$checks" /r:System.IO.Compression.dll /r:System.IO.Compression.FileSystem.dll tests\NormalizerLayoutChecks.cs
if ($LASTEXITCODE -ne 0) { throw 'Test compilation failed' }
$build = 'dist\normalizer-batch-flush'
& $checks "$build\GUI\TinyOPDS.exe" (Join-Path $checkDir 'gui')
if ($LASTEXITCODE -ne 0) { throw 'GUI layout checks failed' }
& $checks "$build\CLI\TinyOPDSCLI.exe" (Join-Path $checkDir 'cli')
if ($LASTEXITCODE -ne 0) { throw 'CLI layout checks failed' }
```

Тест отказывается использовать уже существующий каталог для своих данных. Созданные искусственные архивы остаются в указанном временном каталоге для проверки.
